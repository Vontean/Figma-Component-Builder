# 组件组织

定义组件在家族页中的位置，以及公开组件、Building Block、私有实现之间的组合关系。

## 组件家族页

- 一个页面通常对应一个组件家族，页面内用 `SECTION` 组织 `Component Set` 与独立组件；实际页面结构以目标文件为准。
- 任务明确要求 token 文档时，将其组织为 `Preview` 与 `Token table` 等项目已确认区域。它不同于组件 token 矩阵，不复制矩阵内容。
- 完整使用说明、Annotation、Responsive Layout、Dynamic Font 属于项目 Guideline，不放入组件家族页，除非任务明确要求。
- `Component Set` 是否拆分由 `variant-properties.md` 决定；本文件只决定拆分后组件放在哪里、如何相互引用。

## 三类组件角色

- **公开组件**：业务设计师直接插入和配置的组件。
- **Building Block**：可被多个父组件复用的组件；仅当项目明确暴露时，可直接插入使用。
- **私有实现**：只服务一个父组件的内部图层或子结构，不作为独立组件发布。

先为每个候选对象确定角色，再创建或迁移。没有跨父组件复用价值的对象不抽成 Building Block。

同一职责、结构和 token/Style 绑定在多个变体重复，且抽取能避免维护漂移时，可抽为私有部件；仅尺寸不同不构成抽取理由。私有部件不作为独立组件发布。

私有部件的命名契约见 `anatomy.md`。

## 父子组合

- 父组件通过子组件实例组合，不复制子组件图层。
- 子组件有独立状态或可复用结构时，保留为 Building Block；父组件不重复建立同义状态轴。
- 只有父组件的实例作者需要配置子组件时，才把该选择透传为父组件的 `Component Property`；否则由父组件固定子组件配置。
- 先创建或修复被引用的子组件，再创建父组件；组件引用不得形成循环。

## 旧组件改造

先读取旧组件的页面位置与引用关系，逐一归类为公开组件、Building Block 或私有实现，再向设计师输出组织差异：

- 保留、抽出或收回的组件角色。
- 新建、移除或替换的父子引用。
- 重复组件、断开引用或循环引用。

设计师确认该差异前，不移动、删除或重建组件关系。

## 定位与验证

- 定位现有组件时同时核对页面、节点 ID、类型和位置，不能只按名称判断。
- 同名或重复 `Component Set` 只报告候选，等待设计师决定保留对象。
- 验证每个 Building Block 和公开组件的实例引用正确；私有实现符合 `anatomy.md` 的命名契约，且没有被作为独立组件发布。
